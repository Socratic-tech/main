Guides

Put it online (GitHub Pages)

Create a repo, add this file as index.html, then Settings → Pages → Deploy from branch → main / root. In a minute it's live at your‑name.github.io/repo. The plain address always opens the watch‑only wall.

Open the hidden admin

Add #admin to the address (or tap the small lock, top‑right) to reveal the controls. In Settings → Admin & live control, set an admin passcode so only you and other admins can get back in.

Pick bandwidth + delay

In Settings, leave Relay (Meshcast) on so each player uploads one capped stream like Twitch, and set a delay (3s typical). Test it before the event with a phone stopwatch.

Set up stations + the players code

Players go live themselves

The anti‑cheat delay

The wall displays the configured competition delay, but Meshcast transport is best‑effort and actual timing can vary with the relay, browser, and network. Treat it as a deterrent rather than a frame‑accurate guarantee, and verify it with a visible stopwatch before matches.

Only distribute the wall address to parents. The station IDs are still the direct VDO.Ninja lookup keys, even though the publisher sends its gameplay media through Meshcast.

Always test the real delay before matches start — point a feed at a running stopwatch and measure it. Network conditions and browser versions change the result.

The three doors

  • The wall (default) — the plain URL, and the Share link you send parents. Watch‑only: tiles, a delay indicator, nothing to edit.
  • Admin (hidden) — reach it with #admin or the small lock, top‑right, then your passcode. Everything to build and run the wall lives here.
  • Players (coded) — one entrance link + one access code. Players create their own stream; they never see the wall's controls.

Players & the access code

In Players & stations (admin), make your stations, set a player access code, and copy the players entrance link. Give players that one link and the code. They open it, enter the code, choose their station, type their name, and share their screen — ?push=STATION_ID&screenshare2 does the rest, using the same direct stream ID the wall watches. Their name rides along as the on‑screen label, and the wall's matching station shows them.

  • Stations are the wall's tiles. Create them ahead of time (names or "+ Add open slots"); a player claims one from the entrance.
  • The code gates the create screen, so a link that leaks can't be used to publish without it. Regenerate it anytime.
  • Best capture — sharing an entire screen or a Chrome tab hits ~60fps; a single "window" caps near 42fps. For heavy games, Game Capture or an OBS virtual camera beats browser capture.
  • The browser still shows its own "choose what to share" picker — a security step no link can skip.

Bandwidth — keeping it Twitch‑safe

Plain VDO.Ninja is peer‑to‑peer: every viewer pulls a separate copy straight from the player's PC, so five people watching one player means that player uploads five streams. Relay (Meshcast) mode fixes this — the player uploads one capped stream to a server that fans it out, so their upload stays flat like a Twitch broadcast no matter how many click in. That's the default.

  • Max bitrate per player (Settings) is the upload cap. Relay realistically delivers about 2–3 Mbps 1080p — clean and smooth on the phones and tablets most parents use, though not razor‑crisp esports quality. That's the honest ceiling for a big audience; truly broadcast‑crisp video to a crowd is a Twitch/YouTube job.
  • This build intentionally does not offer a direct-media mode. Player links always include the publisher-side Meshcast relay flag, including older entrance links opened after this file is deployed.
  • Your own download stays light too: the wall keeps one feed open at a time, and dark slots use nothing.

Sharing to parents

Send parents the Share link. It opens a clean, watch‑only version — no editing buttons, just the wall. They click a player to watch, one at a time, all behind your delay. Players "opt in" simply by opening their own link and going live; until then their tile sits dark, and a parent who clicks it sees a short "not live yet" note.

Sound

Audio is on by default — the wall plays a player's sound when you open their feed, if they chose to share it. Because feeds open one at a time, there's never overlapping audio. Tell players: to include game sound they must tick "Share tab audio" (browser game) or "Share system audio" (whole screen) in the share picker — a single app window can't carry sound. Full‑screen audio also captures voice chat, so anyone in team comms should mute if they don't want it heard on the (roughly 3‑second‑delayed) stream.

Why this saves bandwidth

Each slot is a still image until clicked, so parents only receive gameplay media for the station they open. Players publish once to Meshcast; the relay distributes that media instead of asking the player computer to upload a separate video stream to every parent.

What each field does

Solo streams vs rooms

A solo stream is just an ID → ?view=ID. A room feed adds room + scene → ?room=NAME&scene&view=ID. Leave the Stream ID blank on a room feed to show the room's whole layout in one slot.

  • The share link holds your feed names and stream IDs, packed into the URL — no server.

Admin controls

Set an admin passcode in Settings → Admin & live control. Once set, the wall opens locked everywhere — including the parent link — showing only the tiles. Tap the lock icon and enter the passcode to unlock Add, Edit, take‑downs, and the LIVE/OFF switch on that device. Parents never get in.

  • LIVE / OFF (top bar, admin only) pauses the whole wall. Parents see an "Off air" screen and can't open anything.
  • Take down a single feed from its Edit controls — it vanishes for parents and its viewer closes. Restore it the same way.
  • Reaching parents already watching: a plain shared link is a snapshot, so on/off and take‑downs only reach parents when they reload — unless you use one of the two live paths below.

Live path 1 — Director (instant, best for takedowns). If players join through a Room (set one in Players & stations, then "Apply room + password to all"), Settings → Open director room gives you VDO.Ninja's control room. From there you can mute, hang up, or kick any player — the stream itself dies, so it's gone for everyone at once. This is the real kill switch.

Live path 2 — Status file (instant on/off + blocks). Host a small live.json (in your repo or a GitHub gist) and paste its URL into Settings. Every open wall reads it every ~15s and obeys it. Toggle something, hit Copy live.json, paste it into that file, save — parents update within seconds. Format: {"active":true,"down":["streamID"]}.

A determined, technical viewer could read a stream ID out of the share link and watch it directly, bypassing a tile take‑down. The Director/Room path (which kills the actual stream) and stream passwords are what truly stop that — tile hiding is for the honest 99%.

Self‑add (players add themselves)

You don't send individual links. Create stations in Players & stations (use + Add open slots for a quick batch of "Station" tiles), set the access code, and hand out the one entrance link. A player opens it, enters the code, picks a station, types their name, clicks Go live, and shares their screen — that's the whole flow. Numbered stations mean you don't need every name in advance.

Troubleshooting

  • Delay seems short / inconsistent — Meshcast delay is best‑effort and can vary. Always test the real delay before competition and watch on Chrome/Edge.
  • Black screen — the player is offline, the ID is wrong, or it needs a password.
  • Nothing connects — must be HTTPS (GitHub Pages is). School/venue firewalls sometimes block WebRTC.
  • Pop‑out blocked — allow pop‑ups, or use the in‑page viewer.
  • No sound — audio is off per feed by default; edit the feed to enable it.
Needs a modern Chromium browser (Chrome or Edge) served over HTTPS. That's the requirement for the delay to behave.
